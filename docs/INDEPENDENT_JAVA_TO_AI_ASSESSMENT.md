## Assessment for the candidate

**AI application engineering is a credible adjacent direction. Readiness for these
five advertised positions is not yet demonstrated.**

You would not be starting over as an engineer. Your production Java/Spring Boot
services, REST integrations, AWS deployments, SQL optimization, automated testing,
incident support and mentoring are useful foundations for delivering AI-enabled
software. They do not, by themselves, establish experience designing or evaluating
AI systems.

The most important unresolved question is whether you have practical Python and
AI application experience not captured in this profile. If not, the next step is
to develop and demonstrate that capability, rather than collect a long list of tools.
There is no basis here to promise a transition duration or assume seniority will
transfer unchanged.

## Proposed plan: one focused direction

No fixed timeline. These are ordered actions, not guaranteed durations.

1. **Check for omitted relevant experience.** Establish whether Python, AI workflows,
   evaluations or autonomous systems have already been used, and in what context.
   Done when the next steps distinguish existing work from genuinely new learning.
2. **Build or present one AI-backed application.** If no equivalent work exists,
   use the existing backend strengths and add a Python AI service with retrieval
   over owned/synthetic documents. Start with one platform; do not require AWS,
   Azure and GCP together. This is a proposed exercise, not a claim about prior work.
   Done when an end-to-end request works and the candidate can explain the design.
3. **Demonstrate quality and safe operation.** Add a small labeled evaluation set,
   citation checks, poor-answer/empty-retrieval handling, access controls, and
   observable latency/cost/failures. These are practical ways to demonstrate the
   sample's evaluation, reliability and responsible-AI themes, not new universal
   employer requirements. Done when repeatable results and known limitations can
   be shown, not merely a polished demo.
4. **Add accountable delivery experience where possible.** Seek a bounded AI feature
   in a team or legitimate project, with feedback and maintenance responsibility.
   A personal prototype remains a prototype and cannot replace an explicit
   multi-year professional requirement. Done when delivery context and ownership
   can be described accurately; otherwise retain that limitation in applications.
5. **Target application-oriented opportunities selectively.** Use the Specialist
   posting as a work-pattern reference, not a promised opening. Verify location,
   essential AI experience and platform expectations for each opportunity. Do not
   prioritize AI platform/lead roles solely because the current Java title is senior.
   Done when each chosen opportunity has a defensible apply/clarify/defer decision.
